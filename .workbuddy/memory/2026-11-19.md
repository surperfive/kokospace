## 新增：跳过当前影片的投票机制

需求：房主可直接跳过当前视频；其他人只能投票，满 2 票直接切下一部。

改动（协议只在 `roomCore.ts` 一处，三端共用）：
- `RoomVideoState` 新增 `skipVote: { itemId, voters[], threshold } | null`；`SKIP_VOTE_THRESHOLD = 2` 导出。
- 新 action `vote_skip`：重复点 = 撤销自己那一票；票数跟着 `itemId` 走，换片（`advanceToNextItem` / `startItem` / `jump_to`）自动清空；
  退房的人那一票由 `leave()` 自动撤掉，避免「2/2 永远凑不满」。
- 把原来的 `next` 分支抽成 `private advanceToNextItem(playerId, now)`，`next` 与「满票自动切」共用，避免两份推进逻辑漂移。
- 每次投票/撤销/通过都往聊天里推一条 system 消息（`player:chat`），房里其他人看得到谁在投。
- 权限沿用既有模型：`canAdvance()` = 无控片人 / 控片人 / 房主。所以「点播人」仍可直接跳过 —— 如果要收成只有房主能直跳，改 `canAdvance()` 一行即可。
- 待机短片（`isPlaceholder`、无控片人）人人可直跳，不进入投票，这是既有行为。

前端：
- `types/metaverse.ts` 的 `VideoState` 同步加 `skipVote`（可选）。
- `App.tsx` 算 `skipVoteCount / skipVoteThreshold / hasVotedSkip`，新增 `handleVoteSkip`；`canSkipVideo` 为真显示「跳过」，否则显示「投票 / 已投 N/2」。
- 入口两处：巨幕顶栏（`CentralCinemaScreen`，含加载失败浮层里的「投票跳过」）+ 点播单（`VideoQueueDrawer` 跳过选项区、正在播放那一行）。

验证：
- `npx tsc --noEmit` 通过；`npm run build` 通过。
- 单测脚本跑状态机：非房主硬跳被拒、1/2 不切、2/2 切片、撤销归零、退房撤票、换片清票 —— 全对。
- 无头 Chrome（3 个 context）端到端：房主看到「跳过」、客人看到「投票」，客人投票后变「已投 1/2」，第三人投第二票后画面切到下一部且票数归零。

## 新增：聊天里贴视频链接直接点播

需求：在聊天框输入视频链接也能点播。

- 新文件 `src/lib/videoLink.ts`：`detectVideoLink(text)` 纯函数，识别 `.mp4/.m3u8/.webm/.mov/.flv`、
  B 站（`bilibili.com/video/BV…`、`av…`、`b23.tv`、整段「【标题】链接」分享文案）、YouTube、裸 BV 号；
  返回 `{ url, titleHint }`，`titleHint` 是文本去掉链接后清洗过的剩余内容（`【】()` 等符号会被剥掉）。
  **只做识别，不做解析** —— 拿到 url 后仍走 `handleEnqueueUrl`，和点播面板完全同一条链路。
- `App.tsx` 的 `sendChatMessage`：消息照常 `player:chat` 发送，另外 `detectVideoLink` 命中就 `handleEnqueueUrl(url, titleHint)`。
- 输入框下方按状态显示一行：命中链接 →「检测到视频链接 · 发送后会同时点播「标题」」；
  提交后解析期间 →「正在解析链接并点播，请稍候…」（`chatEnqueueing` state，`.finally` 清掉）。
  这行是必须的：`/api/parse-video` 要服务端抓元信息，本机实测海外源要 10~15 秒才返回，
  没有常驻提示的话用户会以为没反应（原来的 2.6 秒 toast 顶不住）。
- 聊天输入 `maxLength` 从 140 提到 300，不然长直链根本 paste 不进去。

## 新增：巨幕小窗（可拖动浮窗，电脑 + 手机）

需求：把正在看的片子缩成小窗口，边逛边看。

- **不复制播放器**。做法是给 `CentralCinemaScreen` 加第三种布局 `isMini`，同一个 DOM 节点从
  「世界坐标 absolute」切成「视口 fixed 320×214」——所以 mp4/hls/YouTube/B站/builtin 画布全都照旧，
  不会出现两个播放器打架、进度不同步。
- `containerStyle` 现在是三级：`isMini ? fixed 浮窗 : isTheaterFocused ? fixed 居中 : absolute 世界坐标`。
  小窗尺寸按视口推：`min(viewport.width*0.62, 320)` 宽，高度 = 宽×9/16 + 34（顶栏）。
- 拖动：顶栏整条是把手，用 **Pointer Events**（`setPointerCapture`），鼠标和手指一套代码。
  点在按钮上不触发拖动（`closest('button')` 提前返回）；`touchAction: 'none'` 防页面被带着滚。
- 位置 `miniPos` 存组件 state，`null` = 默认贴右下角（`right:10, bottom:92`，避开底部操作栏）。
  有 `clampMiniPos()`：**上边界 62px**，否则会被 `z-30` 的顶部导航盖住（小窗是 `z-25`）。
  视口变化（转屏/缩放窗口）时用一个 effect 重新钳制。
- 小窗顶栏只留：标题（截断）、跳过/投票、放大（切影院）、✕（收起回世界）；点播单/控片/只看在小窗里隐藏。
  底部控制条在小窗里直接不渲染（`showBottomControls && !isMini`）。
- `App.tsx`：`isMiniPlayer` state + `handleToggleMini` / `handleToggleTheaterFocus`，两者互斥；
  打开小窗时弹一条 toast 教用户拖顶栏、点 ✕ 收回。
- 入口只有影院顶栏那个 `PictureInPicture2` 按钮：手机底部 dock 已经塞了 8 个按钮（≈414px > 375px 视口），
  再加会溢出，所以没往 dock 里放。

## 新增：小窗里的点播 / 发言 + 聊天气泡

需求：小窗里能点播、能发言（看聊天记录）；别人发言时在小窗画面右下角冒气泡，上浮后消散，约 3 秒。

- **小窗左下角**两个 28px 图标按钮：`ListVideo` = 点播（开片单）、`MessageCircle` = 发言（开聊天面板）。
  没放进顶栏是因为 320px 宽度顶栏已经有标题 + 跳过 + 放大 + ✕，挤不下。
- **聊天气泡**：`CentralCinemaScreen` 新增 props `miniChat` / `onOpenChat`，
  容器 `absolute right-1.5 bottom-1.5 flex flex-col items-end`，`pointer-events-none`，`max-w-[64%]`，`line-clamp-2`。
  动画在 `src/index.css`：`@keyframes miniChatRise` + `.animate-mini-chat`（3s forwards：
  下往上浮 14px 进入 → 停住 → -18px 淡出）；`prefers-reduced-motion` 退化成纯淡入淡出。
- **数据来源**：不用改 WS handler。`App.tsx` 里 `useEffect` 盯 `chatHistory` 末尾，
  发现新 id 就塞进 `miniChatFeed`（`{id,name,text,at}`），这样云端和 P2P 两条链路都能覆盖。
  过滤条件：`isSystem` 不弹（投票播报之类），`Date.now()-createdAt > 5000` 不弹（进房补的历史不弹）。
  另一个 interval（400ms）把 3.2s 前的条目清掉，列表最多留 3 条。
- **叠放不会跳**：容器底边固定、高度向上长，旧气泡（在上面）移除时下面的不动。
  这点一开始我判断反了，实测截图确认没问题。
- 聊天面板在小窗模式下**桌面端挪到左边**（`sm:left-5`），否则 320px 面板正好盖住 320px 小窗；
  手机端不动（面板本来就会临时盖住小窗，关掉就恢复）。聊天输入框加了 `autoFocus`，点「发言」直接能打字。
