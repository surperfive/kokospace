# 2026-11-16

## 改成「GitHub 托管 + Actions 自动部署」，用户以后在云端改代码

**结论先行**：GitHub Pages 不能跑这个项目（静态托管，没有 WS 服务端）。所以做法是
**代码放 GitHub，push 后由 Actions 部署到 Cloudflare Workers**，云端修改用 github.dev。

**新增/改动**：
- `.github/workflows/deploy.yml`（新）：push main / workflow_dispatch → `npm ci` → `npm run build`
  → `cloudflare/wrangler-action@v3` 跑 `wrangler deploy`。需要仓库 secrets：
  `CLOUDFLARE_API_TOKEN`（模板选 Edit Cloudflare Workers）、`CLOUDFLARE_ACCOUNT_ID`。
- `.npmrc`（新）：`legacy-peer-deps=true`，让 CI 的 `npm ci` 不再因 vite8/esbuild peer 冲突失败。
- `src/App.tsx`：WS 地址支持 `VITE_WS_URL` 覆盖（默认仍同源），给「前端放别处」留口子。
- `docs/DEPLOY_GITHUB.md`（新）：4 步接入 + 云端编辑流程 + FAQ + 回滚。
- git 仓库已 `git init -b main`，两次提交：`88a1f1f`（整套部署能力）、`4d59ae1`（GitHub 文档）。
- 改完重新 `wrangler deploy` 过一次，线上与仓库一致（Worker 启动 4ms，v3 版本已生效）。

**踩到的坑**：
1. PowerShell 管道解原生命令输出用 GBK，git 的 UTF-8 中文日志会显示成乱码 —— 实际存储是对的。
   要确认就用 Python `subprocess` 取 bytes 再写文件，看到的才是真值。
2. PowerShell 命令里出现 `%H%n%s` 这类百分号会被安全策略判成 cmd.exe 变量语法直接拦掉，
   取 git 日志改用 `git log -1` 默认格式。
3. `gh` CLI 没装，所以推仓库这步必须用户自己做（建仓库 + 加 secrets + push）。
