## 给 KokoSpace 加了 Cloudflare 部署能力（Workers + Durable Objects）

**背景**：项目原本是 Express + ws 的单进程服务（`server.ts`，房间状态在内存 `Map` 里），
`npm run dev` 起 :3000。用户要求「部署到 Cloudflare，别人点链接直接进房间」。

**结论**：纯 Cloudflare Pages 不行（没有长连接服务端）。走 Workers + Durable Objects：
静态资源用 Workers Static Assets，`/ws?room=xxx` 按房间号路由到 DO，一个房间一个实例。

**新增/改动**：
- `worker/index.ts`（新）：Workers 入口 + `RoomDurableObject`，从 `server.ts` 移植了全部消息协议
  （room:join / player:move / chat / reaction / video:control / scene:update / webrtc:signal），
  默认家具与播放列表、B 站/YouTube 链接解析也一并搬过来。
- `wrangler.jsonc`（新）：assets 绑定 `ASSETS` + `not_found_handling: single-page-application`，
  DO 绑定 `ROOMS`，migration `new_sqlite_classes`（免费计划只能用 SQLite 版 DO）。
- `src/App.tsx`（改）：WebSocket URL 加 `?room=<roomId>`，供 DO 路由。Express 的 `ws` path 匹配
  忽略 query，所以本地老流程不受影响。
- `package.json`：加 `cf:dev` / `deploy` 脚本，`wrangler@^4.162.0`、`@cloudflare/workers-types` 进 devDeps。
- `tsconfig.json`：exclude 加 `worker`；新增 `worker/tsconfig.json` 单独管 workers-types。
- `docs/DEPLOY_CLOUDFLARE.md`（新）：完整步骤 + 坑 + 验证记录。

**验证**：`_scratch/do_test.ts` 24 项桩测试全过；`wrangler dev` 真实 workerd 上 `_scratch/e2e_test.ts`
15 项全过（含静态资源、SPA 回退、房间隔离、离开广播）；无头 Chrome 截图确认前端正常渲染。

**踩到的坑（重要）**：
1. `npm install` 直接失败：`esbuild@^0.25` 与 vite 8 的 peer（`esbuild@^0.27||^0.28`）冲突 → 必须
   `npm install --legacy-peer-deps`。原有的 `bun.lock` 是 bun 装的，不校验严格 peer。
2. 这台机器网络极慢：`npm install` 17 分钟，再装 wrangler 又 40+ 分钟。别以为卡死。
3. wrangler 在 PowerShell 里会打一堆 `NativeCommandError` 红字（其实只是 stderr），用 `2>&1 | Out-File` 再读文件即可。
4. 无头 Chrome 的 `--screenshot=` 必须给**绝对路径**，相对路径报 `Failed to write file ... 0x3`。
5. PowerShell 里 `Get-CimInstance ... | Stop-Process` 杀 wrangler dev 后，那个后台 task 会显示 exit 1，正常。
