## 补齐 GitHub → Cloudflare 的完整链路，并修掉一个会让 CI 直接失败的坑

**用户问题**：怎么通过 GitHub 修改后在 Cloudflare 部署。

**查到的事实**：
- 本地仓库还没配 remote（`git remote -v` 为空），GitHub 上 `surperfive` 名下只有 `portf` /
  `greenbite-lite-meal` / `qing` 三个仓库，**没有 kokospace** —— 所以第一步的「建仓库 + push」还没做。
- 本机没有 gh CLI、没有 git 凭据助手、也没有存储的 GitHub 凭据；但 `~/.gitconfig` 里配了
  `http.proxy=127.0.0.1:7897`，push 时浏览器授权即可。

**修掉的坑（重要）**：
- `package-lock.json` 与 `package.json` 不同步：lock 里没有 `wrangler` 和 `@cloudflare/workers-types`
  （当初是手动往 package.json 里加的）。这会让 GitHub Actions 的 `npm ci` **第一次就跑挂**
  （Missing: wrangler from lock file）。
- 修法：`npm install --package-lock-only` 重建 lock（第一次 502 失败，重试 5 秒成功，
  wrangler 解析到 4.163.0，entries 418 → 505）；同时把 workflow 的 `npm ci` 改成
  `npm install --no-audit --no-fund`，以后在网页里改依赖忘更 lock 也不会挂。

**其它改动**：
- `README.md` 换成真项目说明（技术栈 / 本地开发 / 部署入口 / 目录 / 已知限制），原来还是 AI Studio 模板。
- `docs/DEPLOY_GITHUB.md` 增加第二条路：Cloudflare Workers Builds（Git 直连，不用建 API Token），
  并警告「Actions 和 Builds 只能开一条，否则一次 push 触发两次部署互相覆盖」。
- 三次提交：`88a1f1f` → `4d59ae1` → `82acf61`，工作区干净。

**下一步（等用户）**：建空仓库 `kokospace` → 加两个 secret（`CLOUDFLARE_API_TOKEN`、
`CLOUDFLARE_ACCOUNT_ID`）→ `git push -u origin main`。仓库公开的话，我可以直接用
GitHub API 读 Actions 运行状态来验收。
