## 00:50 手机端「看不到自己的角色」→ P2P 客人没有兜底状态

## 01:05 用户「云端状态下没法同步」→ 找到确切的 bug（fallback 没关分流开关）

**根因**：P2P 失败回落时只清了 `p2pRef`、角标改成「云端」，但 **`p2pEnabledRef` 仍是 true**，
于是 `onmessage` 里的分流分支继续把云端 `player:* / video:* / scene:*` 全部 `return` 掉。
→ 角标显示「云端」，但谁都不同步，只有自己能动。这正是用户看到的现象。

**修法**：抽出 `fallbackToCloud(reason)`：清 `p2pRef` / `isP2PHostRef`、**置 `p2pEnabledRef=false`**、
角标设 cloud、并重新发一次 `room:join` 拉全量状态；`armP2PFallback` 与 `onStatus('failed')` 都走它。

**教训**：加"模式开关 + 消息过滤"这类逻辑时，**回落路径必须和进入路径对称地把开关复位**，
否则就是"界面说回退了、数据仍在被过滤"的静默失败。

部署 `index-x46bfqlA.js`、tsc 0 错误、提交 `3ad60b0`。

## 01:05 用户反馈「进度还是不统一」→ 挖到真正的根因：上报的是时钟，不是播放位置

**根因（两层）**：
1. `progress` 上报值是 `vs.currentTime + (nowServer - vs.updatedAtMs)/1000` —— **服务端时钟的本地外推**，
   而 `vs` 又来自服务端广播，等于"把服务端算出来的数再喂回服务端"，闭环自证。
   点播人视频一缓冲（真实位置落后 3s），上报仍说"我在 35s"，服务端被污染，所有设备一起错。
2. 进度条 `displayTime = getExpectedTime()`（时钟），画面是 `el.currentTime`（真实）——缓冲后必然分离。
3. 次要：`serverTimeOffsetMs` 每条 synced 都用单程到达时间重设，±RTT/2 抖动；
   seek 阈值 0.85s 过大且只在 videoState 变化时校正；拖动进度条每像素发一条 seek，刷屏。

**修法**：
- `CentralCinemaScreen` 新增 `onPlaybackTime`，在 mp4 的 `timeupdate`/`seeked` 回传**真实 `currentTime`**
  （`seeking` 或 `readyState<2` 时不上报，避免 seek 途中把别人拉回去）。
- App 用 `playbackTimeRef` 存它，progress 上报优先用真实位置；内置短片仍用时钟（它本来就是时钟绘制）。
- 逐帧循环接管对齐：**点播人是源，不对齐自己**；其他人 `drift>0.3s` 硬跳、`0.06~0.3s` 改 `playbackRate` 微追（±10%），
  暂停状态也比对位置（>0.3s 直接设）。
- `displayTime` 改为整秒变化才 `setState`（顺带砍掉 60fps 重渲染）。
- mp4 时长用 `onLoadedMetadata` 的真实 `duration`；`getExpectedTime` 对 mp4 用 `Math.min` 不取模（不会循环）。
- offset：120ms 死区 + 半量跟随。
- 进度条拖动：`seekDraft` 本地跟手，停手 200ms 才发一次 seek。
- iframe（YouTube/B站）：`useMemo` 锁 `src`，按当前进度注入起播点（`start=` / `t=`），**播放中无法同步，只保证起播点**。

**线上验收**（`_scratch/sync_test.ts`，12 项全 PASS）：A 上报 45s → B 后进房拿到 46.2s（+1.2s 经过时间）→
A 报到 90s → B 精确 90 → B 的 seek/progress 被拒（reason 正确）→ A 未被污染 → 暂停 100s 双方一致。

**踩到的坑**：自写的 `class Client { open() }` 用 try/catch + `once` error 监听会失败（6 次全挂，undici `processResponse`
非 101），换成 `ws_pair.ts` 那种 `new Promise + settled 标志 + close 监听 + 30s 超时` 立刻通。
另外这台机器首次连 CF 极慢（fetch health 25s），**必须先 fetch 预热再开 WS**。

部署 `index-B9a-Y2eW.js`，tsc 0 错误。
